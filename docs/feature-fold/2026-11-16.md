## FIX

### ff-2026-11-16-01 · cost.py prices Fable 5.2 at the old Fable 5 rate
- **Verdict:** FIX · **Class:** model
- **Changelog (2.1.321):** "Added Claude Fable 5.2 (`claude-fable-5-2`), now the default Fable
  model — 1M context, $8/$40 per Mtok with $0.20/Mtok cache reads"
- **Affected files:** `skills/ux-tournament/scripts/cost.py:22-36` (`RATES`) and `:39-44`
  (`rate_for`, longest-prefix match). `claude-fable-5-2` has no entry, so it matches
  `claude-fable-5` → `(10.0, 50.0, 1.00, 12.5, 20.0)`. That overstates input and output by 25% and
  cache reads by 5×, and the cost meter is the tournament's ground truth.
- **Proposed change:** Add `"claude-fable-5-2": (8.0, 40.0, 0.20, 10.0, 16.0)`. The cache writes use
  the usual 1.25× and 2× of input, which is the convention the Opus 5.5 row already follows. Also
  bump the docstring's "verified" line to say 2.1.321.
- **Risk:** low. The change adds one row, and the prefix logic is unchanged.
- **Test:** `python3 -c "import importlib.util as u; s=u.spec_from_file_location('c','$HOME/.claude/skills/ux-tournament/scripts/cost.py'); m=u.module_from_spec(s); s.loader.exec_module(m); print(m.rate_for('claude-fable-5-2'), m.rate_for('claude-fable-5-1'))"`
  should print `(8.0, 40.0, 0.2, 10.0, 16.0) (10.0, 50.0, 0.25, 12.5, 20.0)`.
- **Patch:** `docs/feature-fold/patches/2026-11-16/ff-2026-11-16-01.patch` (`git apply --check`
  passes against the mirror).

### ff-2026-11-16-02 · Unattended `/loop` and scheduled runs now stop at skills that declare `allowed-tools`
- **Verdict:** FIX · **Class:** automation
- **Changelog (2.1.325):** "Changed scheduled tasks and `/loop` to ask before running a skill that
  declares `allowed-tools` or hooks; add `Skill(name)` to `permissions.allow` to run it unattended"
- **Affected files:** `skills/build-status/SKILL.md:5` (`allowed-tools:`). The same file's `:44`
  (`attended: false` covers "a scheduled or looping agent") and `:386-387` (keeper work "under
  /loop or /unleash") both expect it to run unattended. `commands/update-docs.md:4`
  (`allowed-tools:`) with `:186`, which names `/autonomous-doc-refresh`, the weekly
  doc-consolidation job and `-p` runs as its unattended callers. `commands/harness-audit.md:104`
  suggests automating with `/schedule` or `/loop`, and `commands/harness-audit.md` declares
  `allowed-tools` too. In total, 34 commands and 6 skills declare `allowed-tools`. These three are the
  only ones the harness itself describes running unattended.
- **Proposed change:** In `~/.claude/settings.json`, add `"Skill(build-status)"`,
  `"Skill(update-docs)"` and `"Skill(harness-audit)"` to `permissions.allow`. This only removes the
  new "may I run this skill" prompt. Each skill still runs under its own `allowed-tools` list.
  There's no patch because the fix is in settings, outside the mirror.
- **Risk:** low. The allowlist names three skills you already run unattended.
- **Test:** Before the change, run `/loop 1m /build-status --gates` in a repo that has a build-status
  page. On the first firing, it waits on a prompt to run the skill. After the change, it runs with
  no prompt.
- **Patch:** none (settings change).
