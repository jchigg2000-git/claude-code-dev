## ADOPT

### ff-2026-11-02-01 · Enforce self-improve-loop's write boundary with `permissions.blockWritesOutsideWorkingDirectories`
- **Verdict:** ADOPT · **Class:** packaging (settings)
- **Changelog (2.1.314):** "Added `permissions.blockWritesOutsideWorkingDirectories`: Write, Edit
  and NotebookEdit refuse paths outside the working directories in every permission mode"
- **Affected files:** `skills/self-improve-loop/SKILL.md:14` ("never touches other repos or files
  outside the working tree") and `:36`. Today only the prompt enforces this rule.
- **Proposed change:** Turn the setting on where autonomous loops run, so tools enforce the rule
  that the prose states. Put it in each target repo's `.claude/settings.json`, or pass it with
  `--settings` on unattended runs. Do **not** put it in `~/.claude/settings.json`: skills such as
  `/fold-features` and `/sync-claude-slash` write under `~/.claude` on purpose, and a global
  setting would block those writes. It does not cover Bash writes. Pair it with the sandbox if you
  need that.
- **Risk:** medium. A global placement would break harness-maintenance skills. A per-repo placement
  is low risk.
- **Test:** In a scratch repo, add `{"permissions":{"blockWritesOutsideWorkingDirectories":true}}`
  to `.claude/settings.json`, start `claude`, and ask it to Write `/tmp/ff-test.txt`. The Write
  tool should refuse even in auto or bypass mode. A Write inside the repo should still succeed.
- **Patch:** none. The change goes in settings outside the mirror.
